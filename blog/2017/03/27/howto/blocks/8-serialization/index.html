Blocks学习手册（九） - Serialization

Posted on 2017-03-27 In howto , theano , blocks Views:

Blocks is a framework that helps you build and manage neural network models on using Theano.

概述

保存模型与存储他们的训练过程十分重要：

  1. 神经网络模型训练代价昂贵，需要很长的时间才可以使用。如果训练过程被中途打断的话，我们可以从被停下的地方继续训练就显得十分重要。
  2. 我们保存模型之后也方便我们继续后续的工作，以及分享模型。

上述其实是两个不同方面的需求，这正是Blocks在dump()和load()中需要解决的问题。

Picking the Training Loop

注意：因为在训练过程中序列化/反序列化对象的过程十分复杂，也许会因为某些原因导致调用栈层次太深而出错。所以提高这个上限十分重要。

到运行到检查点时，Blocks将pickle整个main loop的状态，不仅将模型序列化，同时也会将训练的状态（迭代的状态，扩展等）保存下来。但技术上来讲，存在以下困难：

  • 一些Python对象无法被序列化，如文件句柄，生成器，动态生成的类，内部类等
  • theano对象的序列化也困难重重
  • 我们不想将训练数据序列化到内存中，因为这可能占用太多内存

Blocks通过避免序列化某些数据结构如生成器和内部类（参见Developer Guidelines），并复写一些对象的序列化行为，来实现序列化main loop的目的。

但是，长期保存模型还是不太可能，因为：

  • 反序列化要求我们使用的库不能改变。这就意味着我们如果更新了Blocks或者Theano时，就有可能导致反序列化失败
  • theano对象反序列化可能困难重重，特别是将对象从GPU转移到CPU或者相反
  • Python 2/3的反序列化可能并不兼容

Parameter Saving

基于上述原因，Blocks决定拦截所有theano shared variables（其中包括参数）的序列化过程，并将他们保存为单独的NPY文件。保存结果是一个ZIP压缩文件，包括序列化的main loop与一些NumPy数组。这些NumPy数组（包含参数）可以通过方法numpy.load()跨平台读取。这就使我们在main loop序列化失败时读取参数成为可能了。
