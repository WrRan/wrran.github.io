版本控制的历史变化： 本地版本控制系统(Local Version Control Systems, LVCS) => 集中化版本控制系统(Centralized Version Control Systems, CVCS) => 分布式版本控制系统(Distributed Version Control Systems, DVCS)

Git设计目标:

  • 速度
  • 简单的设计
  • 支持 非线性开发模式
  • 完全分布式
  • 支持超大规模项目(速度和数据量)

Git设计思想：

  • Git保存每次更新时的文件快照，不同于其他VCS保存文件的具体差异
  • Git使用基于内容的校验和(checksum)作为数据的唯一标识和索引

图2. Git跟踪文件的完整内容

Git特点：

  • 几乎所有操作都可以在本地执行
  • 多数操作仅添加数据

Git中文件的三种状态：
git中文件有三种状态：已修改(modified)、已暂存(staged)、已提交(committed)；与之对应的是git的三个工作区域：工作目录、暂存区域、本地仓库。具体来说，工作区域是我们进行后续工作的文件目录，本地仓库是git目录（一般为.git文件夹或者使用git clone --bare时的目录本身），暂存区域是git目录下的索引文件。


图3. Git中的三个工作区域

基本的git工作流程如下：

  1. 在工作目录下修改文件
  2. 对文件快照，保存至暂存区域
  3. 提交修改，文件快照转储到git目录中

Git的安装与配置

Windows下的Git安装：到Git for Windows下载EXE文件，运行并安装。
配置文件有三个层次：

  1. 系统配置，/etc/gitconfig文件，对所有用户都适用的配置。使用 git config --system可以修改该配置
  2. 全局配置，~/.gitconfig文件，只对该用户适用。使用git config --global可以修改该配置
  3. 项目配置，[git-project-name]/.git/config文件，只适用于当前项目

在Windows下中系统配置和全局配置文件分别在 Git安装目录下的/etc/gitconfig文件，C:\Users\$USER\.gitconfig。
注意：上述配置中，每个层次的配置都会覆盖上层次相同的配置。

配置用户名、电子邮件用来在每次提交时标注出修改的用户，故而是必需的配置动作。
